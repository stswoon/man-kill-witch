# AGENTS.md

Инструкции для AI-агентов, работающих в этом репозитории. Документация для людей —
`README.md`, дизайн и параметры ощущения — `docs/design.md`.

## Проект

**Man Kill Witch** — браузерный ретро-платформер на Phaser 4 + TypeScript.

- Внутреннее разрешение **320×200**, целочисленный апскейл, тайл **16×16**.
- Логика идёт с фиксированным шагом **1/70 с** (`DT = 1 / 70` в `web/src/scenes/game-scene.ts`).
- Каркаса нет: esbuild собирает один бандл, `tools/build.mjs` публикует игру в `build/`,
  `tools/serve.mjs` раздаёт её.
- Код на TypeScript strict, рендер на Phaser 4 (WebGL). Больше runtime-зависимостей нет.

Статус — ранний прототип. Ассеты в `web/public/assets` временные и подлежат замене;
игровой код переводится на собственный формат данных. Новые ассеты должны быть
оригинальными.

## Агенты

В `.opencode/agents/` два профильных сабагента на `opencode/gpt-6.1-sol#xhigh`
(`mode: subagent` — в меню выбора основной модели их нет, только делегирование):

- `ui-designer-agent` — пиксель-арт: спрайты 24×32, атласы, кадры и тайминги анимаций.
- `music-agent` — музыка и эффекты на WebAudio-синтезе, без аудиофайлов.

Делегируй им визуальные и звуковые задачи; игровую логику и раскладку уровней они не меняют.

## Команды

```bash
npm install
npm run dev        # сборка в build/ + сервер на http://localhost:5173 (или следующем свободном)
npm run build      # сборка в build/: бандл, index.html, ассеты
npm run watch      # esbuild --watch в build/ (удобно вместе с запущенным сервером)
npm test           # tsc по tests + esbuild-сборка тестов + node --test
npm run typecheck  # tsc --noEmit, должен проходить без ошибок
```

`npm run dev` пересобирает `build/` один раз. Для правок в цикле держи `npm run watch`
в отдельном терминале — HMR нет. Watch обновляет только бандл: изменения `web/index.html`
и `web/public/` подхватываются после перезапуска.

Тесты — встроенный раннер Node (`node:test`), без vitest/jest. `tests/*.test.ts`
собираются уже установленным esbuild в `.temp/tests/*.test.mjs`: Node не запускает
эти `.ts` напрямую (parameter properties в `game.ts`, импорты без расширений).
Отдельного watch-режима нет — `npm test` прогоняется целиком за пару секунд.

## Структура

| Путь                           | Назначение                                                                                          |
|--------------------------------|-----------------------------------------------------------------------------------------------------|
| `web/src/main.ts`              | boot Phaser-игры, конфиг рендера, целочисленный апскейл канваса                                     |
| `web/src/scenes/boot-scene.ts` | загрузка ассетов через Phaser Loader, передача их в игровую сцену                                   |
| `web/src/scenes/game-scene.ts` | состояния `title / play / gameover / win`, фиксированный шаг, отладочный `window.mkw`               |
| `web/src/game.ts`              | вся игровая логика: физика, коллизии, враги, пули, двери, предметы, камера. **Без импортов Phaser** |
| `web/src/phaser-view.ts`       | только отрисовка: tilemap, спрайты, камера, HUD, сообщения. **Не меняет состояние игры**            |
| `web/src/assets.ts`            | константы (`TILE`, `SCREEN_W/H`, `TILE_FLAG_MASK`), типы и имена текстур                            |
| `web/src/input.ts`             | клавиатура: `isDown` / `wasPressed`, сброс в конце кадра                                            |
| `web/src/sfx.ts`               | синтезированные WebAudio-блипы                                                                      |
| `web/public/assets/`           | закоммиченные временные ассеты: `tiles.png`, `tileinfo.json`, `levels/*.json`, `sprites/*.png`      |
| `web/index.html`               | подсказка по управлению, CSS канваса                                                                |
| `build/`                       | собранная игра: `bundle.js`, `index.html`, `assets/` (не коммитится)                                |
| `tools/*.mjs`                  | сборка в `build/`, статический сервер, PNG-писатель и сборка тестов (`build-tests.mjs`)             |
| `tests/`                       | тесты логики на `node:test`: физика, враги, правила, данные уровней                                 |
| `docs/design.md`               | дизайн: правила, ощущение, враги, уровни                                                            |

## Правила архитектуры

- Phaser используется как платформа: boot, сцены, загрузчик, tilemap, камера и рендер.
  Физика, ввод с привязкой к фиксированному шагу и звук остаются собственными. Не переводи
  их на Arcade Physics, Phaser Input или Phaser Audio без отдельного решения.
- Игровые правила живут в `game.ts` и не знают про Phaser. Рендер читает состояние
  (`game.level`, `game.enemies`, `game.bullets`, `game.player`, `game.tilePatches`).
- Уровень строится как Phaser tilemap; изменения тайлов во время игры идут через
  `Game.tilePatches` и применяются через `layer.putTileAt()` / `layer.removeTileAt()`.
  Не пересобирай tilemap каждый кадр.
- Любое изменение видимого поведения должно сохранять сетку: координаты и размеры
  кратны тайлу там, где это было задумано; спрайты позиционируются по `Math.round`.
- Индексы тайлов маскируются `TILE_FLAG_MASK` (`0x3ff`): старшие биты — флаги.
- Физические константы в начале `game.ts` — продуктовые. Меняя их, обновляй таблицу
  в `docs/design.md`.

## Стиль кода

- 2 пробела, двойные кавычки, точки с запятой, trailing comma в многострочных литералах.
- Именованные экспорты; типы импортируются через `import type` / `type` в списке.
- Кроме Phaser и esbuild, без сторонних библиотек и без «утилит на будущее»: код должен
  оставаться читаемым.
- Форматирование задаётся вручную — отдельных prettier/eslint-конфигов нет, не добавляй их
  без запроса.

## Ассеты

- `web/public/assets/` закоммичен: следи за diff (PNG — бинарные, смотри глазами).
- Новые спрайты и тайлы — только оригинальные, 24×32 для персонажей, 16×16 для тайлов.
- Не добавляй в репозиторий файлы сторонних игр и их производные.

## Проверка изменений

Минимальный цикл:

1. `npm test` — обязателен. Тесты покрывают физику, врагов, правила и данные уровней;
   падение теста на `content.test.ts` почти всегда означает битый уровень.
2. `npm run typecheck` — обязателен.
3. `npm run build`, затем `npm run dev` и открыть напечатанный в консоли адрес
   (`http://localhost:5173`, если порт занят — следующий свободный).
4. Проверить затронутое: титульный экран → Space, ходьба/прыжок/выстрел, переход через
   дверь, уровни 1–8 по цифрам, смерть и GAME OVER, победа на 8-м уровне.
5. Консоль браузера должна быть чистой; ошибки boot выводятся красным `<pre>` поверх канваса.
6. Для отладки есть `window.mkw`: `mkw.game()`, `mkw.startLevel(n)`, `mkw.step(dt)`,
   `mkw.getState()`, `mkw.renderer`, `mkw.assets`, `mkw.phaser`.

Для правок рендера дополнительно сверяй картинку: пиксель-арт должен оставаться резким
(`pixelArt: true`, `image-rendering: pixelated`), без размытия и полупрозрачных краёв.

## Чего не делать

- Не переносить игровую логику в `phaser-view.ts` / сцены и не тянуть Phaser в `game.ts`.
- Не менять структуру JSON-ассетов без обновления загрузчика и проверки уровней.
- Не «улучшать» раскладку уровней и физику без записи решения в `docs/design.md`.
- Не добавлять CI, линтеры и сторонние тест-раннеры (vitest, jest) без запроса: тесты
  живут на `node:test` + esbuild.
- Не менять физические константы и правила, не поправив `docs/design.md` и `tests/`.
- Не коммитить `build/`, `node_modules/`, `work/`, `.temp/`.
