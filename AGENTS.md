# AGENTS.md

Инструкции для AI-агентов, работающих в этом репозитории. Документация для людей —
`README.md`, дизайн и параметры ощущения — `docs/design.md`.

## Проект

**Man Kill Witch** — браузерный ретро-платформер на PixiJS 8 + TypeScript.

- Внутреннее разрешение **320×200**, целочисленный апскейл, тайл **16×16**.
- Логика идёт с фиксированным шагом **1/70 с** (`DT = 1 / 70` в `web/src/main.ts`).
- Каркаса нет: esbuild собирает один бандл, `tools/serve.mjs` раздаёт `web/`.
- Код на TypeScript strict, рендер на PixiJS 8 (WebGL). Больше runtime-зависимостей нет.

Статус — ранний прототип. Ассеты в `web/public/assets` временные и подлежат замене;
игровой код переводится на собственный формат данных. Новые ассеты должны быть
оригинальными.

## Агенты

В `.opencode/agents/` два профильных сабагента на `opencode/gpt-6.1-sol#xhigh`
(`mode: subagent` — в меню выбора основной модели их нет, только делегирование):

- `ui-designer-agent` — пиксель-арт: спрайты 24×32, атласы, кадры и тайминги анимаций.
- `music-agent` — музыка и эффекты на WebAudio-синтезе, без аудиофайлов.

Делегируй им визуальные и звуковые задачи; игровую логику и раскладку уровней они не меняют.

## Команды

```bash
npm install
npm run dev        # сборка web/bundle.js + сервер на http://localhost:5173 (или следующем свободном)
npm run build      # только бандл
npm run watch      # esbuild --watch (удобно вместе с запущенным сервером)
npm run typecheck  # tsc --noEmit, должен проходить без ошибок
```

`npm run dev` собирает бандл один раз. Для правок в цикле держи `npm run watch`
в отдельном терминале — HMR нет.

## Структура

| Путь | Назначение |
|---|---|
| `web/src/main.ts` | загрузка ассетов, состояния `title / play / gameover / win`, фиксированный шаг, отладочный `window.mkw` |
| `web/src/game.ts` | вся игровая логика: физика, коллизии, враги, пули, двери, предметы, камера. **Без импортов pixi.js** |
| `web/src/pixi-render.ts` | только отрисовка: запекание уровня в `RenderTexture`, спрайты, HUD, сообщения. **Не меняет состояние игры** |
| `web/src/assets.ts` | константы (`TILE`, `SCREEN_W/H`, `TILE_FLAG_MASK`), типы и загрузчики |
| `web/src/input.ts` | клавиатура: `isDown` / `wasPressed`, сброс в конце кадра |
| `web/src/sfx.ts` | синтезированные WebAudio-блипы |
| `web/public/assets/` | закоммиченные временные ассеты: `tiles.png`, `tileinfo.json`, `levels/*.json`, `sprites/*.png` |
| `web/index.html` | монтирование канваса, подсказка по управлению |
| `tools/*.mjs` | статический сервер и PNG-писатель |
| `docs/design.md` | дизайн: правила, ощущение, враги, уровни |

## Правила архитектуры

- Игровые правила живут в `game.ts` и не знают про PixiJS. Рендер читает состояние
  (`game.level`, `game.enemies`, `game.bullets`, `game.player`, `game.tilePatches`).
- Изменения тайлов во время игры идут через `Game.tilePatches`; рендер применяет их
  через `renderer.patchTiles()`. Не перерисовывай весь уровень каждый кадр.
- Любое изменение видимого поведения должно сохранять сетку: координаты и размеры
  кратны тайлу там, где это было задумано; спрайты позиционируются по `Math.round`.
- Индексы тайлов маскируются `TILE_FLAG_MASK` (`0x3ff`): старшие биты — флаги.
- Физические константы в начале `game.ts` — продуктовые. Меняя их, обновляй таблицу
  в `docs/design.md`.

## Стиль кода

- 2 пробела, двойные кавычки, точки с запятой, trailing comma в многострочных литералах.
- Именованные экспорты; типы импортируются через `import type` / `type` в списке.
- Без сторонних библиотек и без «утилит на будущее»: код должен оставаться читаемым.
- Форматирование задаётся вручную — отдельных prettier/eslint-конфигов нет, не добавляй их
  без запроса.

## Ассеты

- `web/public/assets/` закоммичен: следи за diff (PNG — бинарные, смотри глазами).
- Новые спрайты и тайлы — только оригинальные, 24×32 для персонажей, 16×16 для тайлов.
- Не добавляй в репозиторий файлы сторонних игр и их производные.

## Проверка изменений

Автотестов нет. Минимальный цикл:

1. `npm run typecheck` — обязателен.
2. `npm run build`, затем `npm run dev` и открыть напечатанный в консоли адрес
   (`http://localhost:5173`, если порт занят — следующий свободный).
3. Проверить затронутое: титульный экран → Space, ходьба/прыжок/выстрел, переход через
   дверь, уровни 1–8 по цифрам, смерть и GAME OVER, победа на 8-м уровне.
4. Консоль браузера должна быть чистой; ошибки boot выводятся красным `<pre>` поверх канваса.
5. Для отладки есть `window.mkw`: `mkw.game()`, `mkw.startLevel(n)`, `mkw.step(dt)`,
   `mkw.getState()`, `mkw.renderer`, `mkw.assets`.

Для правок рендера дополнительно сверяй картинку: пиксель-арт должен оставаться резким
(`scaleMode: "nearest"`, `image-rendering: pixelated`), без размытия и полупрозрачных краёв.

## Чего не делать

- Не переносить игровую логику в `pixi-render.ts` и не тянуть PixiJS в `game.ts`.
- Не менять структуру JSON-ассетов без обновления загрузчика и проверки уровней.
- Не «улучшать» раскладку уровней и физику без записи решения в `docs/design.md`.
- Не добавлять CI, линтеры, тест-раннеры и новые зависимости без запроса.
- Не коммитить `web/bundle.js`, `node_modules/`, `work/`, `.temp/`.
