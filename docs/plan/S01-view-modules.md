## Цель

Разложить `web/src/phaser-view.ts` на независимые view-модули без изменения поведения,
чтобы арт персонажей, HUD и физику можно было делать параллельно.

## В scope

- Новый каталог `web/src/view/`:
  - `level-view.ts` — построение tilemap, `patchTiles`, камера;
  - `character-view.ts` — спрайты игрока, врагов, пуль;
  - `hud-view.ts` — HUD;
  - `message-view.ts` — титульный экран и текстовые сообщения.
- `web/src/phaser-view.ts` остаётся фасадом с текущим публичным API:
  `showTitle`, `hideTitle`, `showMessage`, `hideMessage`, `buildLevel`, `patchTiles`,
  `render`.
- Перенос кода один-в-один: те же кадры, координаты, глубины, строки HUD, тайминги.

## Вне scope

- Новые анимации, арт, HUD-шрифт, физика, изменение чисел или раскладки.
- Изменение публичного API `PhaserView` и `GameScene`.

## Папки (только эти)

```
web/src/phaser-view.ts
web/src/view/
```

Не трогать чужие папки без согласования в `docs/plan/README.md`.

## Публичный API

`PhaserView` сохраняет конструктор и все методы. `GameScene` не меняется.

## Приёмка

- `npm test`, `npm run typecheck`, `npm run test:e2e`, `npm run build` проходят.
- Титульный экран, HUD и уровень 1 визуально не изменились; консоль чистая.
- В `phaser-view.ts` не осталось логики отрисовки, только композиция view-модулей.
- `game.tick` всё ещё используется ровно там же, где раньше; физика и числа не тронуты.

## Не делать

- Не менять `game.ts`, `game-scene.ts`, ассеты и тесты поведения.
- Не «улучшать» координаты, глубины, строки HUD и кадры.
- Не добавлять новые зависимости.
