# Игровые правила и физика

Числа ниже — продуктовые. Источник точных значений — `web/src/game.ts` и `tests/`; при
расхождении прав код, спеку нужно синхронизировать. Менять числа можно только вместе с
`docs/design.md` и тестами.

## 1. Экран и шаг

| Параметр | Значение |
|---|---|
| Разрешение | `1920×1080` (Full HD) |
| Опорная сетка | `384×216` (1 единица = 5 px экрана) |
| Тайл | `80×80` px (16 единиц сетки) |
| Видимая область | `24×13.5` тайла |
| Шаг логики | `1/70 с` |
| Уровней | 8 |
| Стартовые жизни | 3 |

Мир задаётся в px экрана: все линейные размеры и скорости — прежние значения ×5 (см.
`01-architecture.md` §1.1). Время и тайловая геометрия не меняются, поэтому ощущение
сохраняется; экран 16:9 показывает на 4 тайла больше по ширине и на 1 тайл по высоте, чем
прежние `320×200`. **Решение 2026-11-15: 16:9 принят как есть, уровни 04/08 не меняются.**
Их ширина ровно 24 тайла совпадает с экраном, поэтому горизонтальной прокрутки на них нет.

## 2. Управление

| Клавиша | Действие |
|---|---|
| ← / → (A / D) | ходьба |
| ↑ / ↓ (W / S) | прицел вверх / вниз; ↑ у двери — вход |
| Space | прыжок |
| Ctrl | выстрел |
| 1–8 | отладочный переход на уровень |

`Input` хранит `down` и `hits`. Одиночное нажатие (`wasPressed`) очищается в конце рендер-
кадра. `blur` очищает `down`. Для стрелок, Space и Tab вызывается `preventDefault`.

## 3. Игрок

| Параметр | Значение |
|---|---|
| Тело | `60×120 px` |
| Гравитация | `4900 px/s²` |
| Скорость бега | `660 px/s` |
| Ускорение | `7000 px/s²` |
| Трение | `9000 px/s²` |
| Импульс прыжка | `1500 px/s` |
| Макс. падение | `2600 px/s` |
| Магазин | 8 патронов |
| Кулдаун выстрела | 8 тиков |
| Перезарядка | 26 тиков, только стоя на земле и при `cooldown = 0` |
| Неуязвимость при спавне | 30 тиков |
| Неуязвимость после урона | 60 тиков |

- Разгон и трение применяются к `vx`; при отпущенных клавишах цель — 0.
- Прыжок только с земли; в воздухе Space не перезапускает прыжок.
- Прыжок должен перекрывать 2 тайла с запасом и не доставать до платформы в 3 тайла.
  Ориентир: подъём ~230 px (2.8 тайла).
- Прицел: ↑ → `-1`, ↓ → `1`, иначе `0`; влияет только на вертикальную скорость пули.
- `facing` меняется при ходьбе влево/вправо; при прицеливании не меняется.
- Спавн: маркер `255` в слое entities; игрок ставится в `tx*80 + 10`,
  `ty*80 + 80 - 120`.
- Если игрок ушёл ниже карты, он переносится на `y = 2*80`; за боковые границы
  зажимается в `0..pixelWidth - 60`.

## 4. Выстрел и пули

- Выстрел: Ctrl, `ammo > 0`, `cooldown = 0`. Тратит патрон, ставит `cooldown = 8`.
- Пуля: скорость `1900 px/s` по горизонтали; при прицеле вверх/вниз —
  `vy = ±1900 * 0.75 = ±1425`. Спавн в `(cx + facing*30, cy + aim*30)`.
- Время жизни `40` тиков; после этого удаляется. Жизнь считает `game.ts`, тело пули —
  `arcade/*`; по истечении отправляется `despawnBullet {id}`.
- Хитбокс `15×10` px (рисуется как `15×5`, чтобы попадать по краю).
- Пуля гаснет о тайл, который блокирует движение влево или вправо (проверка по центру
  пули). Односторонние платформы пулю не останавливают.
- Попадание во врага: враг умирает, пуля исчезает, +100 очков.

## 5. Враги

Спавн — из entities. Игнорируются `0`, `255`, значения `>= 0x8000` и неизвестные id.
Начальная позиция: `tx*80 + 10`, `ty*80 + 20`; тело `60×60`; начальное направление — вправо.

| Entity id | Поведение | Скорость | У края |
|---|---|---|---|
| 1, 2 | walker | 130 px/s | разворот |
| 3, 4, 5, 11, 12, 13 | walker | 150 px/s | разворот |
| 6, 7, 9 | charger | 200 px/s | не разворачивается, падает |
| 14–19 | flyer | 170 px/s | игнорирует гравитацию |

- Walker/charger: гравитация и `MAX_FALL`; движение по `x`; при упоре в стену
  `vx = 0` и разворот. Walker на земле проверяет тайл впереди-снизу и разворачивается
  у края. Charger этого не делает.
- Flyer: `phase += dt*2.4`; `x += dir*speed*dt`; `y += sin(phase)*120*dt`; разворот при
  блокировке впереди на середине высоты. Погибает при `y < 40` или
  `y > pixelHeight - 120`.
- Касание игрока при `invuln = 0`: −1 жизнь, вспышка `hurtFlash = 40`. Если жизни
  кончились — `gameOver`; иначе игрок возвращается на маркер спавна с `invuln = 60`.
  Враги при этом не переспавниваются.
- Визуальный вид врага задаётся `Enemy.sprite` и старыми группами кадров; S05 сохраняет
  эти визуальные варианты. Поведение и скорости не меняются.

## 6. Двери, предметы, очки

### Дверь (D9)

- **До открытия** дверь — обычные тайлы уровня: блок `2×3` (2 тайла в ширину, 3 в высоту),
  начиная с `(tx-1, ty-1)`, где `(tx, ty)` — тайл с behavior `1`/`2` под центром игрока.
  Спрайта нет; триггерный дверной тайл проходим, твёрдые боковые тайлы области (например,
  `51`, `75`, `272`) остаются стеной до открытия.
- Статичная дверь использует индексы тайлсета, которые обязаны сохраниться по D10:
  ```
  17, 48, 49, 51, 75, 78, 79, 90, 91, 92, 104, 105,
  251, 252, 264, 265, 272, 277, 278, 369, 382, 395,
  583, 584, 596, 597, 609, 610, 620, 621, 622, 623,
  633, 634, 635, 636, 646, 647, 648, 649, 724, 725,
  726, 727, 737, 738, 739, 740, 832, 833
  ```
  Это часть 501 используемого тайла; отдельного «легаси-набора кадров открытия» больше нет.
  `51`, `75`, `272` — твёрдые боковые тайлы, попадающие в область `2×3`; они очищаются при
  открытии, как и раньше очищались старыми патчами (только теперь на 5 тиков раньше).
- **Срабатывание:** дверь открывается прицелом вверх — на тике, когда активной двери нет,
  игрок держит `ArrowUp`/`KeyW`, и триггерная клетка behavior `1`/`2` находится в тайле
  центра игрока или на одну клетку выше него (арка стоит на голову выше центра). Прыжок и
  простое касание дверь не открывают: это защищает от случайного завершения уровня при
  проходе через дверь. При срабатывании `Game` создаёт состояние
  `{tx, ty, step: 0, timer: 0}` и очищает все **внутрикартные** ячейки области `2×3` до
  `0`, добавляя их в `tilePatches`. За пределами карты ячейки не трогаются. С этого
  момента view показывает `door-open` (кадр 0), статичные тайлы двери скрыты.
- **Шаги:** каждый следующий тик `timer++`; при `timer = 5` — `timer = 0`, `step++`.
  `step = 1` и `2` не меняют тайлы (анимация спрайтовая), `step = 3` завершает уровень:
  `levelComplete = true`, `+1000`, `door = null`. Всего **15 тиков** от срабатывания.
- **Анимация:** `door-open` — 3 кадра по 5 тиков: кадр 0 виден с 0-го по 5-й тик, кадр 1 —
  с 5-го по 10-й, кадр 2 — с 10-го по 15-й. Показываются все три кадра, включая ранее
  пропущенный `DOOR_FRAMES[0]`. Спрайт `s_door.png` — `160×240` (3 кадра, лист `480×240`),
  ставится в `(tx-1)*80, (ty-1)*80`, origin `0,0`, глубина позади персонажей.
- `DOOR_FRAMES` в `game.ts` удаляется; `Game.door` становится публичным read-only состоянием
  для view.
- **Тест:** `tests/game.test.ts` меняется: вместо 12 патчей проверяются состояние двери и
  очистка 6 ячеек (для тестовой арены), затем `step = 1` через 5 тиков, `step = 2` через
  10, завершение и `+1000` через 15.
- `docs/design.md` (раздел «Правила», строка про дверь) исправлен S08 на `2×3` и описание
  «статичные тайлы + спрайт открытия».

### Подборы

| Behavior | Эффект |
|---|---|
| `52` | +100 очков, тайл очищается |
| `53` | +250 очков, тайл очищается |
| `54` | +500 очков, тайл очищается |
| `105`–`109` | +1 патрон (не выше 8), тайл очищается |

Изменения тайлов идут через `Game.tilePatches`; рендер применяет их через
`layer.putTileAt` / `layer.removeTileAt`. Tilemap не пересобирается.

### Очки и жизни (D11)

- **Прохождение (run)** — это `RunState { lives, score, nextExtraLife }`, принадлежит
  `GameScene` и передаётся в `Game`. Новое прохождение: `lives = 3`, `score = 0`,
  `nextExtraLife = 5000`.
- Враг: +100. Уровень: +1000.
- Дополнительная жизнь: пока `score >= nextExtraLife`, `lives++`, `nextExtraLife += 5000`;
  порог переносится между уровнями.
- **Переход на следующий уровень** (дверь): тот же `RunState`; очки, оставшиеся жизни и
  `nextExtraLife` сохраняются.
- **Смерть внутри уровня**: `lives--`; очки и `nextExtraLife` сохраняются; респавн на маркере
  спавна. При `lives = 0` — `gameOver`, прохождение завершено.
- **Game over**: Space рестартует **текущий уровень** с новым прохождением: 3 жизни, 0 очков,
  `nextExtraLife = 5000`. Счёт/жизни погибшего прохождения не переносятся.
- **Win**: Space начинает новое прохождение с уровня 1: 3 жизни, 0 очков, 5000.
- **Титульный экран**: Space начинает новое прохождение с уровня 1.
- **Отладочные 1–8 и `mkw.startLevel(n)`**: новое прохождение с уровня `n`; 3 жизни, 0
  очков, 5000 — чтобы отладка была предсказуемой.
- **`mkw.advanceLevel(n)`** (S12): переход на уровень `n` с тем же `RunState`; только для
  e2e-проверки переноса.
- Сохранение — только в памяти вкладки; `localStorage`/сервер не используются, после
  перезагрузки страницы прохождение начинается заново.

## 7. Камера

- Окно `1920×1080`, следует за центром игрока: `round(cx - 960)`, `round(cy - 540)`.
- Зажимается в `0..pixelWidth - 1920` и `0..pixelHeight - 1080`; на уровне меньше экрана
  остаётся в `0,0`.
- Позиции спрайтов при рендере округляются.
- `camera.zoom` не используется: масштаб мира задан константами (`TILE = 80`).
- Уровни 04 и 08 шириной 24 тайла (`1920` px) ровно совпадают с экраном: горизонтальной
  прокрутки на них нет, вертикальная остаётся.

## 8. Формат уровней и tileinfo

- `LevelData`: `width`, `height`, `tiles[]`, `entities[]` (плоские массивы
  `width*height`). Размеры — в тайлах; `pixelWidth = width * 80`, `pixelHeight =
  height * 80`. JSON уровней под HD не меняется.
- `TILE_FLAG_MASK = 0x3ff`; старшие биты — флаги, индекс тайла маскируется.
- `TileInfoData`: `count`, `blockUp`, `blockDown`, `blockLeft`, `blockRight`, `flags`,
  `behavior` — массивы длины `count`.
- `Level.blocks` — по направлению; вне карты считается блокирующим. `tileAt` вне карты
  возвращает `-1`, `behaviorAt` — `0`.
- `Level.setTile` сохраняет старшие биты ячейки и маскирует новый индекс; вне карты
  игнорируется.
- `tileinfo.json` описывает 858 тайлов; уровни используют 501 различный ненулевой индекс
  (факт репо). `tests/content.test.ts` проверяет покрытие индексов, размеры, спавн и
  наличие двери.
- Структуру JSON-ассетов нельзя менять без обновления загрузчика и проверки уровней.

## 9. Состояния сцены

| Состояние | Поведение |
|---|---|
| `title` | Показан титульный экран. Space/Enter — старт уровня 1. |
| `play` | Симуляция и рендер. 1–8 — переключение уровня. |
| `gameover` | Сообщение `GAME OVER` / `PRESS SPACE`. После 30 тиков Space/Enter — рестарт уровня. |
| `win` | `CONGRATULATIONS!` / `THE WITCH IS GONE — PRESS SPACE`. После 30 тиков Space/Enter — уровень 1. |

- Завершение уровня: следующий уровень; на 8-м — `win`.
- HUD: `LVL {n}/8   LIVES {lives}` и `AMMO {ammo}   SCORE {score}` (три пробела между
  группами).
