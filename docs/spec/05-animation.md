# Анимации

## 1. Решение

Все анимации персонажей и врагов идут через Phaser AnimationManager (`this.anims`).
Кадры больше не выбираются вручную по `game.tick`.

Анимация — визуальный слой (D6):

- её фаза не входит в детерминированную симуляцию;
- она не влияет на урон, патроны, двери, очки и переходы;
- игровые таймеры остаются тиковыми `1/70`;
- частота кадров задаётся в fps и подобрана из прежних тиковых таймингов:
  `70 / 5 = 14 fps` для героя, `70 / 8 = 8.75 fps` для врагов.

## 2. Раскладка листов

Новый арт рисуется с нуля (см. `03-art.md`) и обязан сохранить эту раскладку. Старые листы
уже используют эти кадры, поэтому S05 (арт) и S06 (анимации) независимы.

| Текстура | Файл | Ячейка | Кадры | Назначение |
|---|---|---|---|---|
| `hero` | `sprites/s_hero.png` | `24×32` | 14: `0…13` (лист `336×32`) | используются 0 — idle, 1–6 — run, 13 — jump; 7–12 — резерв |
| `chunk1` | `sprites/s_chunk1.png` | `24×32` | 35: `0…34` (лист `168×160`) | 7 групп врагов по 5 кадров |
| `chunk2` | `sprites/s_chunk2.png` | `24×32` | 20: `0…19` (лист `120×160`) | 4 группы врагов по 5 кадров |
| `door` | `sprites/s_door.png` | `32×48` | 3: `0…2` | анимация открытия; до открытия дверь — тайлы уровня |

Все персонажи нарисованы **смотрящими влево**, как старый арт. View ставит
`flipX = true` при движении вправо (`facing > 0` / `dir > 0`). S06 **не меняет** flip-логику,
поэтому S05 (арт) и S06 (анимации) независимы.

## 4. Код

- `web/src/animation-catalog.ts` — чистые данные, **без импорта Phaser**. Экспортирует тип
  `AnimationSpec` и массив/карту `ANIMATIONS`.
- `web/src/animations.ts` — `registerAnimations(scene: Phaser.Scene)`: создаёт анимации через
  `scene.anims.create` и `generateFrameNumbers`; если ключ уже существует — пропускает
  (защита от повторной регистрации при перезапуске сцены).
- Регистрация вызывается из `CharacterView` (S06) после загрузки текстур. BootScene грузит
  текстуры до старта GameScene, поэтому кадры уже доступны.
- `web/src/view/character-view.ts`:
  - игрок: `play(key, true)`; выбор ключа по `onGround` и `abs(vx)`; `flipX = facing > 0`;
    позиция `round(x + w/2)`, `round(y + h)`;
  - враги: спрайт создаётся с текстурой по `Enemy.sprite` (2–8 — `chunk1`, 9–12 —
    `chunk2`); ключ `enemy-<Enemy.sprite>`; `flipX = dir > 0`; мёртвый/скрытый —
    `setVisible(false)` и `anims.stop()`;
  - никакого `Math.floor(tick / N)` и `setTexture(key, frame)` для анимированных спрайтов.
- `Enemy.sprite` и `SPRITE_BY_ID` не меняются: визуальные варианты врагов сохраняются.
- Каталог не содержит **логики** игровых событий; `door-open` — данные анимации. События
  (урон, смерть, дверь) остаются в правилах.

## 5. Визуальные варианты врагов

Старые группы спрайтов сохраняются: один `sprite` id — один **новый собственный** силуэт и
одна анимация. Старые силуэты не копируются; визуальное разнообразие сохраняется. Это не
требует менять `game.ts` / `tests/enemy.test.ts`.

|---|---|---|

| 3 | `chunk1` 5–9 | 2 |
| 4 | `chunk1` 10–14 | 3 |
| 5 | `chunk1` 15–19 | 6 |
| 6 | `chunk1` 20–24 | 4, 5 |
| 7 | `chunk1` 25–29 | 9 |
| 8 | `chunk1` 30–34 | 7 |

## 6. Дверь (D9, S10)

- **До открытия** дверь — статичные тайлы уровня в области `2×3`; спрайта нет. Индексы
  статичной двери обязаны сохраниться в новом тайлсете (список — в `02-gameplay.md`).
- При срабатывании `Game` отдаёт состояние `{tx, ty, step}`, очищает внутрикартные ячейки
  `2×3` (2 по X, 3 по Y) и добавляет их в `tilePatches`. View ставит `s_door.png` в
  `(tx-1)*16, (ty-1)*16`, origin `0,0`, глубина позади персонажей, и проигрывает
  `door-open`: 3 кадра × 5 тиков = 15 тиков, все три кадра, включая ранее пропущенный
  `[0]`.
- Уровень завершается на 15-м тике; `+1000`; спрайт скрывается вместе с переходом.
- `DOOR_FRAMES` и старые кадры открытия не используются; статичные дверные тайлы — да.
- Каталог `door-open` добавляет S10 (каталог создан S06).

## 7. Приёмка

- `tests/animation-catalog.test.ts` (S06) проверяет ключи, текстуры, диапазоны кадров,
  fps > 0 и `repeat`.
- `tests/art-assets.test.ts` (S05) проверяет размеры PNG и число кадров `hero`, `chunk1`,
  `chunk2` по IHDR и ширине ячейки; без новых зависимостей.
- `npm run test:e2e`: загрузка без ошибок, анимации не ломают состояния; дверь до открытия —
  тайлы, при открытии — спрайт, 3 кадра, 15 тиков.
- Ручная проверка: idle/run/jump героя; все визуальные варианты врагов; смена направления;
  смерть врага; отсутствие «дёрганья» при смене анимации; шов двери с тайлмапом.
- Никаких предупреждений Phaser о повторной регистрации анимаций.
